# SpatialViewer.CadCore v0.12.13

## 中文

v0.12.13 继续处理湘源地块“色块已恢复，但地块代码仍缺失”的实机问题。

### 证据

v0.12.12 实机结果已经确认：

- 115 个 `LZX_LAND / AcdbLzxLand` 地块色块可正确显示；
- Proxy Graphics 中没有 Text primitive；
- 图纸同时存在 `YD-A33 / YD-B1 / YD-G1 ...` 等用地层，以及独立的 `YD-CODE` 图层。

因此这一版不猜湘源私有 payload，而只恢复图层名已经明确携带的显示代码。

### 新增

对于同时满足以下条件的对象：

1. 明确 Xiangyuan identity；
2. `LZX_LAND / AcdbLzxLand`；
3. 所在层为 `YD-<code>`；
4. 已有闭合 proxy LwPolyline 边界；
5. 尚无 native semantic decoder；

CadCore 会把 `YD-` 后缀作为显示代码，例如：

- `YD-A33 -> A33`
- `YD-B1 -> B1`
- `YD-G1 -> G1`
- `YD-U22 -> U22`

文字会被放到真实的 `YD-CODE` Scene 图层，而不是塞进地块图层，因此关闭 `YD-CODE` 后代码也会随之隐藏；文字颜色使用 `YD-CODE` 图层自身解析出的 CAD 颜色。

位置基于已恢复的地块闭合边界计算内部点，文字高度按地块局部尺度自适应。

### 边界

这仍是 display fallback，不声明已经解码湘源原生地块属性。不会生成或猜测容积率、密度、绿地率、高度、地块编号、备注等其他字段。

- Product/File/Informational version: `0.12.13`
- CLR ABI: `1.0.0.0`
- Host Contract: `SpatialViewer.CadHost >=1.0.0,<2.0.0`
- Release manifest schema: `2`

## English

v0.12.13 restores Xiangyuan parcel-code labels for the real-device case where v0.12.12 already renders land-use fills correctly but the `LZX_LAND` proxy stream contains no text.

For an explicitly Xiangyuan `LZX_LAND / AcdbLzxLand` parcel on a `YD-<code>` layer, CadCore derives the display label from the source layer suffix and publishes the generated text on the real `YD-CODE` scene layer. The label therefore obeys the source layer's visibility and color controls. Placement is computed inside the decoded closed parcel boundary.

This is a display fallback only and does not claim native private-field semantics.

ABI, Host Contract and manifest schema are unchanged.

## 日本語

v0.12.13 は、v0.12.12 で用途色面が正しく表示された一方、`LZX_LAND` proxy stream に Text が存在しないため欠落していた地块コード表示を補完します。

明示的な Xiangyuan `LZX_LAND / AcdbLzxLand` が `YD-<code>` layer にある場合、`YD-` suffix を表示コードとして使用し、実在する `YD-CODE` scene layer に text node を追加します。そのため `YD-CODE` の表示/非表示と CAD color をそのまま継承します。

これは display fallback であり、private parcel semantic の解読を意味しません。

ABI、Host Contract、manifest schema は変更ありません。
