## SpatialViewer.CadCore v0.8.0

### 中文
- 新增通用、reader-independent 的二维场景空间索引。`Scene2D` 在第一次空间查询时按最终世界坐标 AABB 懒构建不可变 BVH，并随 Scene 生命周期缓存；未使用空间查询的小图纸不会强制承担索引构建成本。
- 新增 `Scene2D.QueryItems(worldBounds)` 与 `SceneSpatialIndexStatistics`。局部查询只返回与查询区域相交的候选项，同时严格保持原始 Scene 绘制顺序和实时图层可见性。
- `HitTesting.HitTest` 已接入空间索引：先以拾取点和 world tolerance 形成查询框缩小候选集合，再执行原有精确几何命中算法；重叠对象仍按原有逆绘制顺序优先拾取最上层图元。
- `RenderPreparation` 新增带 `Size2D viewport` 的重载，可利用 Camera 可见世界范围进行 viewport culling，并支持以屏幕像素表示的 overscan；原有全场景 `Prepare(scene, camera)` 保持兼容。
- v0.6 引入的继承式 `ClipBounds` 已自然进入索引，因为索引使用 flatten 后、与 clip 相交后的最终 `SceneItem.Bounds`，视口外被裁掉的几何不会重新进入局部候选集合。
- 对 NaN/Infinity 等无法安全进入 BVH 的非有限 bounds 采用保守 fallback：这些项不会导致空间索引漏掉潜在内容，而是在查询时始终作为候选保留。
- 100,000-item core benchmark 现在额外记录空间索引构建、局部查询候选数、局部查询与 indexed HitTest，为后续大图纸优化保留稳定基线；本版不以易受 runner 波动影响的绝对毫秒数作为兼容承诺。
- CLR ABI 继续保持 `1.0.0.0`，产品/文件版本独立推进至 `0.8.0`。

### 日本語
- Reader に依存しない共通 2D Scene Spatial Index を追加しました。`Scene2D` は最初の Spatial Query 時に final world-space AABB から immutable BVH を lazy build し、Scene の lifetime に合わせて cache します。Spatial Query を使わない小規模図面には強制的な index-build cost を課しません。
- `Scene2D.QueryItems(worldBounds)` と `SceneSpatialIndexStatistics` を追加しました。局所 query は領域と交差する candidate のみを返しつつ、元の Scene draw order と live layer visibility を保持します。
- `HitTesting.HitTest` は point + world tolerance の query box で candidate を絞ってから従来の exact geometry hit test を実行します。重なった entity の topmost priority は従来どおり reverse draw order で保持されます。
- `RenderPreparation` に `Size2D viewport` を受ける overload を追加し、Camera の visible world bounds による viewport culling と pixel-based overscan を可能にしました。既存の全 Scene `Prepare(scene, camera)` は互換のままです。
- v0.6 の inherited `ClipBounds` は flatten 後の final `SceneItem.Bounds` に反映されるため、そのまま spatial index に組み込まれます。Viewport clip 外の geometry が局所 candidate に復活することはありません。
- NaN/Infinity など安全に BVH 化できない bounds は conservative fallback candidate として保持し、performance optimization のために correctness を失わない設計にしています。
- 100,000-item core benchmark に index construction、local candidate count、spatial query、indexed hit test を追加しました。Runner に依存する絶対 millisecond 値を互換性保証としては扱いません。
- CLR ABI は `1.0.0.0` のまま、product/file version は `0.8.0` に進みます。

### English
- Adds a reader-independent 2D scene spatial index. `Scene2D` lazily builds an immutable BVH from final world-space AABBs on the first spatial query and caches it for the scene lifetime, avoiding mandatory index-build cost for small scenes that never use spatial queries.
- Adds `Scene2D.QueryItems(worldBounds)` and `SceneSpatialIndexStatistics`. Local queries return only intersecting candidates while preserving original scene draw order and live layer visibility.
- `HitTesting.HitTest` now narrows candidates with a point-plus-world-tolerance query box before running the existing exact geometry hit algorithms. Overlapping objects retain the original reverse-draw-order topmost selection priority.
- `RenderPreparation` adds a `Size2D viewport` overload that uses camera-visible world bounds for viewport culling and supports screen-pixel overscan. The existing full-scene `Prepare(scene, camera)` remains compatible.
- Inherited `ClipBounds` from v0.6 naturally participate because indexing uses flattened `SceneItem.Bounds` after clip intersection; geometry clipped outside a viewport is not reintroduced as a spatial candidate.
- Non-finite bounds such as NaN/Infinity use a conservative fallback path instead of entering the BVH, ensuring the optimization never silently drops potentially visible content.
- The dependency-free 100,000-item core benchmark now records index construction, local candidate counts, spatial queries, and indexed hit testing. v0.8.0 deliberately does not promise runner-sensitive absolute millisecond thresholds.
- CLR ABI remains stable at `1.0.0.0`; product/file version advances independently to `0.8.0`.

### Scope boundary
v0.8.0 establishes static spatial acceleration for the current flattened 2D Scene model. It does not claim dynamic incremental BVH mutation, out-of-core/streaming CAD loading, GPU command batching, level-of-detail simplification, or tiled geometry storage; those are separate later performance layers rather than being conflated with this index milestone.
