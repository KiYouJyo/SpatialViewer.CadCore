# SpatialViewer.CadCore v0.11.0

## 中文

v0.11.0 是 CadCore 的“天正兼容基础”里程碑。它不尝试在一次更新中反向实现完整天正 BIM 对象，而是先建立一条可靠的兼容链：识别应用自定义类、保证未知插件实体不被 Reader 静默丢弃、保留对象身份与 CLASSES 信息，并在源文件提供可信 Proxy Graphics 时把安全的二维子集作为 fallback 显示。

### 天正与自定义对象识别

- 新增 reader-independent `CadCustomClassDefinition` 与 `CadCustomEntity`，插件对象不再与普通 `CadUnsupportedEntity` 混为一谈。
- 保留 CLASSES 表中的 DXF 类名、C++ 类名、应用名、class number、instance count、proxy flags 与 proxy/zombie 状态。
- 采用保守的天正识别规则：`TCH_*` 是直接强信号，同时识别明确的 Tianzheng / TArch / 天正应用身份；仅仅在无关 C++ 类名里出现 `Tangent` 不会被误判为天正。
- 文档级 metadata 增加 `TianzhengDetected`、`TianzhengClassCount`、`TianzhengEntityCount`、`CustomClassCount`、`CustomEntityCount` 等兼容性统计。

### Reader 边界不再静默丢对象

- ACadSharp 的 unknown-entity 保留选项默认关闭。CadCore 现在对 DXF/DWG Reader 显式启用 `KeepUnknownEntities`，保证由 CLASSES 表识别的应用自定义实体能够进入 CadCore 适配层。
- DXF 自定义对象按其真实自定义 DXF 名（例如 `TCH_WALL`）与 CLASSES 表关联，并以 `UnknownEntity` 路径保留；DWG 中 ACadSharp 已解析出的 ProxyEntity / Proxy Graphics 也进入同一 reader-independent 兼容模型。
- Model Space、普通块定义与 Paper Space 均参与兼容性扫描；Model layout 不再重复统计 Model Space 实体。
- 对无法原生解释的对象输出汇总兼容性诊断，而不是假装已经恢复其天正参数语义。

### Proxy Graphics 二维 fallback

- 新增 reader-independent `CadProxyPrimitive`，首批支持 Polyline、Polygon、Circle、CircularArc。
- 当 ACadSharp 已经提供可信、平面的二维 Proxy Graphics 时，CadCore 会把这些代理几何转换为通用 Scene 几何，因此对象可以进入既有渲染、bounds 与 picking 管线。
- fallback Scene 保持原 custom-object `ObjectId`，并明确标记 `CustomProxyFallback=True`、`NativeSemanticsDecoded=False` 与 `ProxyTraitsApplied=False`。
- 如果代理流包含尚未支持的 model-transform 或 clip 状态命令，CadCore 会保留对象但拒绝把坐标直接画出来，避免产生位置看似合理、实际错误的假兼容。
- 本版本尚未解释 proxy color/fill traits，因此 Polygon 当前只作为轮廓 fallback，不宣称填充、颜色、线型完全还原。

### 回归与兼容性

- 新增真实 DXF Reader 回归：CLASSES 中的 `TCH_WALL / TDbWall / Tianzheng Architecture` 身份能够 round-trip，并且自定义 `TCH_WALL` 实体在 Reader→CadCore 边界不会消失。
- 新增四类 Proxy Graphics 的 reader-independent Scene 回归、ACadSharp 3.7.1 映射回归，以及 transform-state 阻断回归。
- 产品、FileVersion 与 InformationalVersion 更新为 `0.11.0`。
- CLR ABI 继续保持 `1.0.0.0`。
- Host Contract 继续保持 `SpatialViewer.CadHost >= 1.0.0` 且 `< 2.0.0`；SpatialViewer 本体产品版本仍不参与内核更新资格判断。

### 明确未声明为完整支持的范围

v0.11.0 **不宣称完整天正建筑语义支持**。墙、柱、门窗、轴网、楼梯、房间、标高/索引/尺寸等对象的原生参数解析属于 v0.12；结构、给排水、暖通、电气属于更后续阶段。本版本也不宣称已支持全部 Proxy Graphics 类型、model-transform/clip 指令、proxy traits、任意 3D 代理几何，或从天正对象参数重建 BIM 关系。对于没有可用 Proxy Graphics 的自定义对象，CadCore 会保留身份和 metadata，但不会凭空生成图形。

## English

v0.11.0 is the Tianzheng compatibility-foundation milestone for CadCore. It does not attempt to reverse-engineer the complete Tianzheng BIM object model in one release. Instead it establishes a reliable compatibility chain: identify application-defined classes, prevent unknown plug-in entities from being silently discarded by the reader, preserve class/object identity, and render a conservative 2D subset when trustworthy Proxy Graphics are available.

### Tianzheng and custom-object identification

- Added reader-independent `CadCustomClassDefinition` and `CadCustomEntity`, keeping application-defined objects distinct from ordinary `CadUnsupportedEntity` values.
- Preserves DXF class name, C++ class name, application name, class number, instance count, proxy flags, and proxy/zombie state from the CLASSES table.
- Uses conservative Tianzheng identification: `TCH_*` is a strong direct signal, with explicit Tianzheng / TArch / 天正 application identities also recognized. An unrelated C++ class containing only `Tangent` is not classified as Tianzheng.
- Document metadata now reports `TianzhengDetected`, class/entity counts, and corresponding custom-object counts.

### Reader boundary no longer silently drops custom entities

- ACadSharp disables unknown-entity retention by default. CadCore now explicitly enables `KeepUnknownEntities` for both DXF and DWG readers so application-defined entities recognized through the CLASSES table survive into the adapter.
- DXF application objects are associated by their actual custom DXF name, such as `TCH_WALL`, and retained through ACadSharp's `UnknownEntity` path. DWG ProxyEntity / Proxy Graphics already decoded by ACadSharp feed the same reader-independent compatibility model.
- Model Space, ordinary block definitions, and Paper Space participate in compatibility inventorying without double-counting Model Space through the Model layout.
- Unsupported native semantics produce explicit aggregate compatibility diagnostics rather than false claims of a native Tianzheng decode.

### 2D Proxy Graphics fallback

- Added reader-independent `CadProxyPrimitive` support for Polyline, Polygon, Circle, and CircularArc.
- Trustworthy planar 2D proxy primitives already decoded by ACadSharp are converted into normal Scene geometry, allowing them to use existing rendering, bounds, and picking pipelines.
- Fallback geometry retains the custom object's `ObjectId` and is explicitly marked with `CustomProxyFallback=True`, `NativeSemanticsDecoded=False`, and `ProxyTraitsApplied=False`.
- If a proxy stream contains model-transform or clip state commands not yet implemented, CadCore preserves the object but withholds geometry instead of drawing coordinates at a potentially wrong location.
- Proxy color/fill traits are not interpreted yet. Polygon therefore remains outline-only in this milestone rather than claiming native fill or style fidelity.

### Regression and compatibility

- Added real-DXF reader regression for `TCH_WALL / TDbWall / Tianzheng Architecture` CLASSES identity and preservation of a custom `TCH_WALL` entity across Reader → CadCore.
- Added reader-independent Scene tests for the four initial proxy primitives, ACadSharp 3.7.1 mapping coverage, and an explicit transform-state blocking regression.
- Product, file, and informational versions advance to `0.11.0`.
- CLR ABI remains `1.0.0.0`.
- Host Contract remains `SpatialViewer.CadHost >= 1.0.0` and `< 2.0.0`; SpatialViewer application versions remain outside kernel update eligibility.

### Explicit non-claims

v0.11.0 does **not** claim complete native Tianzheng Architecture semantics. Native parameter decoding for walls, columns, doors/windows, grids, stairs, rooms, elevations/index symbols/dimensions is the v0.12 milestone; structure, plumbing, HVAC, and electrical disciplines remain later work. This release also does not claim every Proxy Graphics type, model-transform/clip commands, proxy traits, arbitrary 3D proxy geometry, or reconstruction of BIM relationships from Tianzheng object parameters. Custom objects without usable Proxy Graphics retain identity and metadata but do not receive invented geometry.

## 日本語

v0.11.0 は CadCore の「天正互換基盤」マイルストーンです。一度の更新で天正 BIM オブジェクト全体を逆実装するのではなく、アプリケーション定義クラスの識別、未知プラグイン entity の消失防止、CLASSES/オブジェクト ID の保持、そして信頼できる Proxy Graphics が存在する場合の保守的な 2D fallback 表示という互換チェーンを先に確立します。

### 天正・カスタムオブジェクトの識別

- reader-independent な `CadCustomClassDefinition` と `CadCustomEntity` を追加し、アプリケーション定義オブジェクトを通常の `CadUnsupportedEntity` と区別します。
- CLASSES テーブルの DXF class 名、C++ class 名、application 名、class number、instance count、proxy flags、proxy/zombie 状態を保持します。
- 天正判定は保守的です。`TCH_*` を強い直接シグナルとし、明示的な Tianzheng / TArch / 天正 application identity も認識します。無関係な C++ class 名に `Tangent` が含まれるだけでは天正と判定しません。
- `TianzhengDetected`、class/entity 数、custom-object 数を document metadata に追加します。

### Reader 境界でカスタム entity を消失させない

- ACadSharp は unknown entity の保持を既定で無効にしています。CadCore は DXF/DWG Reader の `KeepUnknownEntities` を明示的に有効化し、CLASSES で認識されたアプリケーション定義 entity を adapter まで保持します。
- DXF のカスタムオブジェクトは `TCH_WALL` のような実際の custom DXF 名で CLASSES と関連付け、ACadSharp の `UnknownEntity` 経路から保持します。DWG で ACadSharp が解析済みの ProxyEntity / Proxy Graphics も同じ reader-independent 互換モデルへ入ります。
- Model Space、通常 block definition、Paper Space を互換性集計対象とし、Model layout 経由で Model Space を二重計上しません。
- ネイティブ意味を解釈できない場合は明示的な互換性 diagnostic を残し、天正パラメータを解読済みとは扱いません。

### Proxy Graphics 2D fallback

- reader-independent な `CadProxyPrimitive` を追加し、初期対応は Polyline、Polygon、Circle、CircularArc です。
- ACadSharp が既に復号した信頼できる平面 2D Proxy Graphics は通常の Scene geometry に変換され、既存の描画・bounds・picking パイプラインを利用できます。
- fallback geometry は custom object の `ObjectId` を維持し、`CustomProxyFallback=True`、`NativeSemanticsDecoded=False`、`ProxyTraitsApplied=False` を明示します。
- 未対応の model-transform / clip 状態命令が proxy stream に含まれる場合、オブジェクト自体は保持しつつ geometry の描画を抑止し、誤った位置への表示を避けます。
- proxy の color/fill traits はまだ解釈しないため、Polygon は現段階では輪郭 fallback のみです。

### 回帰・互換性

- `TCH_WALL / TDbWall / Tianzheng Architecture` の CLASSES identity と custom `TCH_WALL` entity が Reader → CadCore で消失しないことを実 DXF Reader 回帰で確認します。
- 4 種類の初期 Proxy Graphics に対する reader-independent Scene 回帰、ACadSharp 3.7.1 mapping 回帰、transform-state の明示的な抑止回帰を追加しました。
- Product / File / Informational version は `0.11.0` に更新します。
- CLR ABI は `1.0.0.0` のままです。
- Host Contract は `SpatialViewer.CadHost >= 1.0.0` かつ `< 2.0.0` を維持し、SpatialViewer 本体の製品バージョンは kernel update eligibility に使用しません。

### 完全対応を宣言しない範囲

v0.11.0 は**天正建築の完全なネイティブ意味解析を宣言しません**。壁・柱・建具・軸網・階段・部屋・標高/索引/寸法などのネイティブパラメータ解析は v0.12、構造・給排水・空調・電気はさらに後続の段階です。また、全 Proxy Graphics type、model-transform/clip 命令、proxy traits、任意 3D proxy geometry、天正パラメータからの BIM 関係再構築も本バージョンの完全対応範囲ではありません。利用可能な Proxy Graphics がない custom object は、identity と metadata を保持しますが、架空の geometry は生成しません。
